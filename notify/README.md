# $bog_gram_notify

Клиент пуш-демона: подписка браузера плюс её регистрация на сервере. Демон держит endpoint у себя, а не в ленде: в публичном ленде ключи подписки означали бы, что слать пуши может любой прохожий.

- `supported()` — по http воркер не регистрируется, а ожидание готового так и висит. Лучше честно сказать «не поддерживается», чем подвесить кнопку.
- `activated()` — живой жест пользователя. Без него Safari и Firefox запрос разрешения отклоняют не спрашивая, а Chrome показывает тихую плашку, которую почти никто не замечает: выглядит как «нажал, и ничего». Где свойства нет, полагаемся на браузер.
- `permission_request()` — только запрос разрешения, без подписки. Он должен быть первым действием фибры: любое подвисшее чтение до него перезапустит фибру уже в микрозадаче, и жест к тому моменту протухнет.
- `subscribe( lord, monitor )` — разрешение, подписка в браузере и отправка её демону. Наружу не падает: при отказе тумблер просто остаётся выключенным. Ключ демона не кэшируется, он мог смениться вместе с томом демона. Старую подписку под другой ключ браузер обновить не даст, поэтому она сперва снимается целиком. Ключ приезжает в base64url, браузер ждёт сырые байты.
- `unsubscribe( lord )` снимает подписку с обеих сторон. Браузерной может уже не быть, это не повод не сказать демону, что слать больше некому.
- POST-ы уходят без заголовка типа: строка едет как text/plain, это простой CORS-запрос без preflight, а демон всё равно разбирает JSON.
- Промисные браузерные API собраны одной кучей: фибра дёргает их через синхронную обёртку, внутри только голые `await`.

## Воркер

`notify.web.ts` исполняется и как страница, и как сервис-воркер. `lib.dom` знает только страницу, поэтому формы воркерных событий описаны вручную.

- Пустое или чужое тело пуша не повод молчать: показывается заглушка, иначе браузер сам нарисует «This site has been updated in background».
- Клик по уведомлению фокусирует открытую вкладку, а без неё открывает новую.
