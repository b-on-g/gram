# Gram

Простой мессенджер на [$mol](https://mol.hyoo.ru/) и [Гипер Базе](https://baza.giper.dev/): local-first, p2p-синхронизация через мастер-узлы, шифрованные диалоги. Аккаунт — пара ключей в браузере, никакой регистрации.

**[Открыть](https://b-on-g.github.io/gram/)** · **[Исходники](https://github.com/b-on-g/gram)**

## Как это устроено

Архитектура по разбору Карловского:

- **user** — публичный профиль в home-ленде: имя + ссылки на служебные ленды
- **dialogs** — приватный шифрованный список диалогов и известных владельцу реестров
- **dialog** — шаренный между участниками ленд: участники + сессии
- **session** — отдельный ленд-бакет с сообщениями и позициями прочтения
- **message** — порядок задаётся полем Moment в данных, а не порядком доставки
- **inbox** — лобби-ленд для доставки инвайтов, заявок в группу и отказов (писать могут все, с PoW). Лобби открытое, поэтому каждая запись запечатана общим ключом пары `secret_mutual` Гипер Базы: ссылку на диалог или группу читает только адресат, а подделку без приватного ключа отправителя печать не пропускает
- **users** — реестр для обнаружения собеседников: название задаёт создатель, вступают по кнопке
- **monitor** — публичный список лендов для будущего пуш-сервиса

## Модули

Корень `$bog_gram` — дирижёр: заводит доменные объекты, связывает их в дереве и решает, какие страницы стоят в книге. Логики экранов в нём нет.

- Схема: `user`, `users`, `dialogs`, `dialog`, `session`, `message`, `read`, `inbox`, `note`, `key`, `device`, `devices`, `monitor`. Пояснения к полям и тесты лежат рядом с каждой сущностью.
- Домен: `account` (свои ленды, ключ, лобби), `registry` (реестры пользователей), `people` (имена, подписи, ключи собеседников), `talk` (модель диалога), `roster` (список диалогов, архив, запросы), `crew` (состав групп), `lobby` (приглашения и заявки через чужие лобби), `invite` (личная ссылка), `alerts` (пуши).
- Страницы: `menu` (список диалогов), `chat` (открытый диалог, по странице на диалог), `settings`, `compose`, `group`, `members`, `music`. Общая основа страницы — `page`.
- Компоненты: `row` (строка списка), `bubble` (пузырь сообщения), `hold` (кнопка удержания), `attach` (выбор файла со сбросом), `avatar`, `field`, `photo`, `sound`, `zoom`.
- Помощники: `pass`, `lord`, `clock`, `count`, `soft`, `tone`, `seal`, `shrink`, `voice`, `link`, `notify`, `push`, `auth`, `mine`, `nozoom`, `scan`, `version`.

## Корень

- Чат открывается только явно выбранным диалогом: на узком экране он не должен открываться сам. Избранного нет в списке диалогов, но открывается оно так же.
- Кнопки «новый диалог», «новая группа», «настройки» в шапке списка работают переключателями: повторный клик закрывает уже открытую страницу.
- Экран участников есть только у группы: в переписке вдвоём перечислять некого.
- Страница музыки после первого открытия остаётся в книге и при закрытии только прячется: фрейм, убранный из документа, выгружается вместе с плеером, а музыка должна играть дальше.
- На новом устройстве ленд избранного приезжает не мгновенно: пока он в пути, строка стоит с пустым превью, а не вешает весь список.
- Ширину страницам задаёт только `width`: книга сама даёт им `flex-shrink: 0`, а `$mol_page` — `max-width: 100%`. На телефоне ширина упирается во вьюпорт, и буклет листается горизонтальным снапом; `shrink`/`grow`/`min-width` поверх этого ломают адаптивность.

### Тема

- Мост `--bog_builderui_*` → `--mol_theme_*` и палитры светлой и тёмной темы лежат в `gram.view.css`.
- `bog_gram_current` — выбранное (история в участниках) красится как выбранный диалог. `bog_gram_armed` — взведённая кнопка ждёт второго клика и красная. Подпись кнопки лежит во вложенной вьюхе со своим цветом, поэтому перекрашивается отдельно, иначе текст сливается с фоном.
- Мобильные повадки браузера, из-за которых приложение ощущается сайтом: iOS увеличивает страницу при фокусе в поле со шрифтом мельче 16 px и обратно не отматывает, поэтому у полей ровно 16 px; резиновая прокрутка и «потяни, чтобы обновить» выключены; серая вспышка по тапу и задержка двойного тапа на кнопках погашены.

Мастера — штатная общая сеть Гипер Базы из сида. Переопределяются штатным параметром Базы `#!giper_baza_yard_masters=<url>[,<url>]`.

Ссылки: `#!invite=<лорд>` открывает личный диалог сразу, `#!join=<ленд группы>` шлёт заявку — ключ от шифрованной переписки выдаёт админ поимённо, мгновенно вступить нечем. `#!users=<ленд реестра>` запоминает реестр.

## Ссылки открываются в установленном приложении

В манифесте заданы `scope: ./` и `handle_links: preferred`, поэтому установленное приложение забирает себе все ссылки внутри `https://b-on-g.github.io/gram/`.

- Android: при установке Chrome лепит WebAPK с интент-фильтрами на scope, и присланный инвайт открывается сразу в Gram. Если система не подтвердила связь сама, помогает переключатель в настройках приложения: «Открывать поддерживаемые ссылки».
- Desktop Chrome начиная со 139 перехватывает ссылки в установленное приложение сам. `launch_handler: navigate-existing` переиспользует уже открытое окно вместо второго, а состояние всё равно живёт в хеше, так что `hashchange` доводит приложение до нужного экрана.
- iOS ссылки в веб-приложение не отдаёт, там остаётся запуск с домашнего экрана.

Иконки в манифесте тут не украшение: без них Chrome не считает приложение устанавливаемым, WebAPK не создаётся и перехватывать ссылки некому. Лежат в `logo/`, попадают в сборку строкой `deploy` в `gram.meta.tree`.

Приложение строит ссылки из `location.pathname`, так что слэш на конце есть всегда. Если ссылку набирают руками, слэш лучше не терять: `/gram` без слэша сначала уходит в редирект, а редирект перехват может не пережить.

Своего домена у приложения нет, `/.well-known/assetlinks.json` лежал бы в корне `b-on-g.github.io` и из этого репозитория туда не дотянуться. WebAPK этот файл и не требует, он нужен нативным приложениям и TWA.

## Запуск локально

```sh
npm create view-tree-lsp@latest gram
npx mam bog/gram
# http://localhost:9080/bog/gram/-/index.html
```

Локальный мастер: `node giper/baza/app/run/-/node.js port=9090`, затем `#!giper_baza_yard_masters=http%3A%2F%2Flocalhost%3A9090%2F`.

## Версия

Версия показывается в настройках и лежит в `version/version.ts`. Хук `pre-commit` поднимает последнее число на каждый коммит и сам кладёт файл в коммит. В свежем клоне хук включается один раз:

```sh
git config core.hooksPath .githooks
```
