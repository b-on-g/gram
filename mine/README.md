# $bog_gram_mine

Своего хранилища у Gram больше нет: юниты и болы Гипер Базы лежат в общей базе
домена `$giper_baza_mine` — той же, что у Music. Один аккаунт на все приложения
означает и одно локальное хранилище: иначе одни и те же ленды качались бы дважды
и расходились при сбросе.

Модуль остался ради разового переноса из старой базы `bog_gram_mine` и ради двух
защит вокруг неё.

- **Перенос идёт с ключами.** Стор заведён без `keyPath`, с автоинкрементом, а
  База ищет записи по `[ ленд, путь ]`. Поэтому `put` без явного ключа выдал бы
  записям числовые ключи, и База не нашла бы ни одного юнита. `copy()` тащит
  пары через `getAll` и `getAllKeys` и кладёт их под прежние ключи.
- **Чтение перенос не ждёт.** Перенос идёт в фоне. Гейт на `units_load` опасен:
  если транзакция не закроется, промис не разрешится, `$mol_action` подвесит
  рендер, и приложение навсегда останется на «Загружаем данные аккаунта…». Без
  гейта худшее — База прочитает кеш до переноса и докачает недостающее с
  мастеров, как на новом устройстве.
- **Внутри транзакции запросы идут подряд, без `await`.** Транзакция
  IndexedDB закрывается, как только управление отдаётся событийному циклу:
  следующий запрос упал бы, а `commit()` повис бы навсегда. Ждём только
  завершения транзакции.
- **Первая версия переноса оставляла мусор.** Она писала без ключей, и такие
  записи лежат в общей базе под числовыми ключами. `clean()` их выкидывает: это
  кеш, настоящие данные живут на мастерах.
- **Старая база не удаляется.** Она маленькая и служит резервной копией: если
  перенос окажется неудачным, не придётся тянуть всё заново с мастеров.

Ключ аккаунта — тоже общий, см. `$bog_gram_auth`.
