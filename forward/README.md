# $bog_gram_forward

Пересылка сообщения в другой чат и обмен контактом. Это два разных действия: пересылают содержимое, а контактом делятся осознанно и ровно туда, куда хотят.

## Пересылка

`copy( source, target )` пишет в свежий бакет целевого чата копию: текст, кадры альбома, голосовое, видео, карточку контакта. Новое сообщение помечено `Forwarded`, автор у него я, время текущее: иначе сломались бы порядок и отметки прочтения.

- Автора оригинала в копии нет: ни лорда, ни имени. Людям целевого чата, которых автор не знает, он не раскрывается.
- Ссылки на исходный чат тоже нет, и ответ (`Reply`) не переносится: цитата указывала бы туда, куда у получателей нет доступа.
- Вложения переносятся байтами в новые закрытые ленды с правом чтения только у участников целевого чата. Выдать право на исходный ленд нельзя: его выдаёт только тот, кто вложение загрузил, и тогда получатели читали бы ленд чужого чата.
- Вложение должно быть уже скачано у пересылающего. Недоехавший ленд файла отдаёт пустой буфер, а не ожидание, и переслать пустоту было бы хуже, чем сказать «откройте и повторите» (`forward_unloaded`).
- Сначала читаются все вложения, потом пишется сообщение: прерванная на чтении попытка не оставляет в чате полупустой копии.
- Ключи участников нужны только для вложений. Текст и контакт лежат в бакете, который и так зашифрован для всех участников.
- Звонок не пересылается: комната звонка принадлежит исходному чату.

## Контакт

`contact( lord, target )` кладёт в чат сообщение с ключом человека (`Contact`) и именем, которое он сам себе выбрал (`Contact_name`). Моя подпись для него остаётся моей и не уходит. Без известного ключа делиться нечем (`contact_unknown`).

`contact_lord( pass )` считает лорд из ключа. Получатель по кнопке «Написать» передаёт ключ в `$bog_gram_people.pass_learn`, который сверяет его с лордом, и открывает диалог: ключ уже есть, искать его по реестрам не нужно.
