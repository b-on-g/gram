# Форк приватного ленда

## Что случилось 9 ноября

После входа в аккаунт на новом устройстве у Кирилла пропали подписи контактов, диалоги стали «неизвестными», вылезли давно отклонённые запросы, исчезла созданная им группа.

Все приватные записи аккаунта лежат в одном ленде: список диалогов, скрытые, принятые, архив, подписи контактов (`Notes`), своё имя (`Name`). Указатель на него — атом `Dialogs_land` в домашнем ленде, а заводится ленд так:

```ts
const str = this.user_store().Dialogs_land()?.val()
return str ? this.land( String( str ) ) : this.dialogs_land_make()
```

`ready()` зовёт это на старте. На новом устройстве или после чистки браузера IndexedDB пуста и отвечает за миллисекунды, мастер — за сотни. Код видит «указателя нет», заводит новый пустой ленд и пишет на него указатель. Запись свежее и побеждает на всех устройствах. Старый ленд никуда не делся, на него просто никто больше не указывает.

Указатель к тому времени форкался уже пять раз: 3, 4 (дважды), 7 и 9 ноября. Живым был ленд от 7 ноября, ещё четыре диалога лежали в форке от 4-го.

Тем же образом устроены `Watch_land` (монитор пушей) и `Devices_land`. Их форк — вероятная причина того, что уведомления «сами выключаются».

## Как восстановили

Атом хранит запись каждого устройства отдельно, поэтому все прежние ссылки на месте:

```js
const account = $bog_gram.Root(0).Account()
const atom = account.user_store().Dialogs_land()
atom.units_of( null ).map( unit => [
	$giper_baza_time_dump( unit.time(), unit.tick() ),
	String( atom.land().sand_decode( unit ) ?? '' ),
] )
```

Синхронный вызов в консоли не дождётся загрузки ленда: подписка живёт ровно один вызов, и чтение навсегда остаётся «ждёт». Читать надо через фибру:

```js
const peek = $mol_wire_async( ( link )=> {
	const store = account.land( link ).Data( $bog_gram_dialogs )
	return {
		dialogs: store.Dialogs()?.items().length ?? 0,
		hidden: store.Hidden()?.items().length ?? 0,
		notes: store.Notes()?.keys().length ?? 0,
		name: String( store.Name()?.val() ?? '' ),
	}
} )
await peek( '<ссылка>' )
```

Главным выбран ленд с именем и большинством диалогов. Затем:

- из остальных форков дописали недостающие диалоги (кроме уже скрытых в главном), принятых, архив добавленных и подписи, которых в главном не было;
- скрытые из сегодняшнего форка не переносили: это удаления, сделанные вслепую, и среди них были живые диалоги;
- вернули указатель: `account.user_store().Dialogs_land( 'auto' ).val( main )`.

Скрипт сначала читает всё и только потом пишет: `$mol_wire_async` перезапускает тело на каждом ожидании, и запись до чтения задвоилась бы.

Удаление диалога ничего не стирает: ленд диалога и права в нём остаются, меняются только списки в приватном ленде. А вот `list.cut` пишет на место элемента `null`, поэтому вырезанный из `Dialogs` id по самому списку уже не найти.

## Что поправить

1. **Не заводить ленд на старте.** `dialogs_land()`, `monitor_land()`, `devices_land()` только читают указатель. Пустой указатель значит «ещё не знаю», а не «ленда нет». Заводит ленд только явное действие из фибры (первая запись), и только когда домашний ленд точно доехал с мастера. Если сигнала «догнал мастера» в Базе нет, первое правило ничего не решает, и нужно второе.
2. **Список вместо указателя.** Рядом с атомом держать `$giper_baza_list_str` всех заведённых лендов. Список сливается, а не перетирается. Читать изо всех, писать в один. Тогда форк перестаёт быть потерей, а уже случившиеся форки подхватываются сами из `units_of( null )` старого атома.
3. **Не писать из отсутствия.** `names_fill` и `name_hide` пишут производное значение по ещё не доехавшему состоянию. Пустое имя не должно перезаписывать непустое: писать только по намерению человека или только в пустое место.
4. **Не давать разрушать вслепую.** Пока приватный ленд не доехал, не показывать диалоги «неизвестными» как готовое состояние. Удаление, которое синкается на все устройства, — отменяемое: раздел «Скрытые» в настройках с кнопкой «Вернуть».
5. **Тест** на холодный старт второго устройства: указатель приезжает позже первого чтения, ленд не заводится, данные первого устройства видны.

Пока это не сделано: не входить в аккаунт на новых устройствах и не чистить браузер.
