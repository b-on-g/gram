# $bog_gram_talk

Модель одного диалога по его ссылке: участники, группа и админы, бакеты, сообщения, прочтения, строка в списке. Сюда же входит избранное, диалог с самим собой.

## Избранное

Заметки для себя лежат в приватном шифрованном ленде, ссылка на него хранится в `$bog_gram_dialogs`, а не в открытом профиле.

- `saved_land()`: захват небыстрый, и клик по строке может позвать его второй раз, поэтому уже записанная ссылка всегда важнее только что захваченной. Ленд заводится только по явному клику: список диалогов приезжает не мгновенно, и на свежем устройстве пустая ссылка какое-то время выглядит как «ленда ещё нет». Захват на старте приложения попадал в это окно всегда.
- `saved_id()`: ссылка на уже заведённый ленд. Строка избранного рисуется с первого кадра, а ждать захвата список не должен.
- `saved_links()`: все ленды заметок аккаунта, указанный последним. Их больше одного, если избранное успело завестись на двух устройствах сразу. Читаем изо всех, пишем в указанный.
- `saved_is( id )`: единственная развилка на всё приложение. У избранного нет собеседника, поэтому ни галочек, ни счётчика непрочитанных, ни «Вы:» в превью. Заброшенный ленд заметок остаётся избранным наравне с указанным: иначе открытая с него страница схлопывалась бы сама, а отправка молча ничего не делала.

## Участники и группа

- `lords( id )`: все участники, включая меня. Ленд может быть ещё не засинкан, и чтение приостанавливается. Это правильно: по этому списку выдаются права, и неполным он быть не должен.
- `mates( id )`: все, кроме меня: кому выдавать права и чьи прочтения считать.
- `group_is( id )`: третий участник делает переписку группой. Названная тоже группа, даже если в ней пока двое: название заводят осознанно, и от того, что кто-то вышел, группа обратно в личную переписку не превращается.
- `group_title( id )`: название косметика, ждать его незачем. `group_name_auto( id )` подписывает группу без названия её участниками: список имён говорит больше, чем «5 участников».
- `group_title_set( id, title )`: название лежит в общем ленде группы и видно всем. Менять его может админ, у остальных поля нет, но решение принимается тут.
- `owner( id )`: королём ленда числится служебный ключ, поэтому создатель записан прямо. Ссылка приезжает из лобби, открытого на запись всем, и мусор вместо неё обычное дело: весь список из-за одной такой строки падать не должен.
- `own( id )`: моя ли переписка. У заведённых до появления записи о создателе спросить некого, поэтому смотрим на права: полное управление получает тот, кто ленд захватил.
- `admin_is( id, lord )`: создатель админом остаётся всегда.
- `member_rank( id, lord )`: чтобы админ мог выдать право новому человеку, ему нужно полное управление лендом, а вместе с ним он получает и возможность менять чужие права. Разделить эти способности в Базе нечем.

## Бакеты

Бакетов больше одного, когда кого-то убрали из группы или добавили без истории: ключ от уже выданного бакета отобрать нельзя, и переписка продолжается в свежем. Читаем изо всех, до каких дотягиваемся. У избранного делить нечего, его ленд сам себе единственный бакет.

`land_of( id )` и `session( id )`: свежий бакет, в него уходит вся запись. Берётся по явному указателю `Session_last`, а не по хвосту списка: порядок в списке задаётся слиянием, и после ротации запись ушла бы в покинутый бакет. Хвост остался запасным путём для старых диалогов.

## Сообщения и прочтения

- `messages_merge`: бакеты идут друг за другом во времени, а не вперемешку, поэтому склеиваются целиком по моменту своего первого сообщения. Внутри бакета порядок списка. Совпавшие начала разводятся ссылкой, иначе бакеты менялись бы местами от синка к синку. Сортировать все сообщения по `Moment` нельзя: первое чтение поля сообщения в Базе стоит десятые доли миллисекунды, и на 3000 сообщениях одна сортировка вешала старт на секунды.
- `last( id )`: последнее живое сообщение ищется с хвоста. Строке списка (момент, превью, время, «есть ли переписка») хватает его одного, остальные сообщения она не трогает.
- `unread_since( messages, my, seen, limit )`: счёт идёт с хвоста и останавливается на своей отметке прочтения и на сотне: больше 99 меню всё равно не показывает. Без отметки иначе читалась бы вся переписка.
- `messages_of( id )`: бакет, который не читается (не приехал, не расшифровался, прав не выдавали), пропускается. Один недоступный не уносит с собой всю переписку, а лента дособерётся сама.
- `read_moment_of( id, lord )`: своя отметка пишется в последний бакет, но человек читает переписку целиком, а не по отсекам. Ответ это дальняя отметка изо всех бакетов. Пока отметка едет, чтение ждёт, а не отдаёт ноль: иначе диалог открылся бы с первого сообщения. Своё последнее сообщение (`wrote_moment_of`) тоже отметка: кто ответил, тот видел всё до ответа. Без этого переписка, которую читали не в фокусе или с другого устройства, после перезагрузки показывала десятки непрочитанных под собственным ответом, а собеседник не видел двух галочек.
- `mine_among` и `mine_wrote( id )`: есть ли моё живое сообщение, ищется с хвоста. Отсюда два вывода: приглашение до первого своего сообщения никуда не едет, а диалог, где я уже отвечал, запросом быть не может.

## Строка списка

- `moment( id )`: последняя активность, по ней сортируется список. Недоступное заменяется нулём, список пересортируется сам.
- `alive( id )`: есть ли живое сообщение. Пока ленд не приехал, сообщений «нет», и чужой диалог ждёт снаружи списка.
- `preview( id )`: вложение называется словом, подпись идёт следом. В группе перед текстом имя написавшего.
- `avatar_id( id )`: пока ленд в пути, кружок пустой. У группы собеседника нет, узор рисуется по ссылке на её ленд.
