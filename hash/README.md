# $bog_gram_hash

Запоминает хеш юнита Гипер Базы, пока байты юнита не менялись.

В Базе `hash()` юнита идёт в `$giper_baza_link.hash_bin( this.asArray() )`. Кеш там по объекту массива, а `asArray()` каждый раз создаёт новый `Uint8Array`, так что кеш не срабатывает никогда. При загрузке ленда из IndexedDB один и тот же юнит хешируется 4–6 раз: в `$giper_baza_unit_sort`, дважды в `unit_seal_inc`, в `unit_seal`, в `rate_min`. На профиле старта с большой историей это треть времени `diff_apply`.

Переопределение хранит копию байтов рядом с хешем. Если байты совпали, отдаётся прежний хеш, иначе он считается заново. Хеш берётся от всего буфера вместе с подписью, а пишут в буфер мимо методов (`sign`, `data`), поэтому сброс по записи не годится, только сравнение. Сравнить пару сотен байт дешевле, чем посчитать SHA на JS.

Уйдёт, когда это поправят в самой Базе.
